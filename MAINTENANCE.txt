个人网站维护说明

这是直接手写维护的静态网站：HTML 是正文，CSS 是排版。
学术页面不使用 JavaScript；所有页面均不使用 Hexo、jQuery、外部字体库、CDN 或 npm 包。
课余小站 /playground/ 下的梗图库使用本站的原生 JavaScript 提供筛选与收藏；另有无脚本的完整图片索引。
托管仍使用原来的 GitHub Pages。仓库根目录就是发布目录。

常用文件
  index.html         简介和 News；新增动态放在列表顶部
  .local/seminars/   暂时下线的讨论班页面和首页区块备份（不发布）
  notes/index.html   笔记列表；新增 PDF 后添加一条列表项
  notes/*.pdf        研究和学习笔记
  blog/index.html    博客目录；目前还没有正文文章
  .local/CV.pdf      暂时下线的简历备份；此目录被 Git 忽略，不会随网站发布
  css/site.css       学术页面排版（包括手机和打印样式）
  playground/        课余小站入口，使用独立样式，不影响学术页面
  playground/bandori/ 邦邦梗图库、轻量网页图片、静态索引和来源记录
  404.html           页面不存在时显示的页面
  img/               原有图片，文件仍然保留
  .nojekyll          让 GitHub Pages 直接提供静态文件

页面都是完整 HTML。即使浏览器禁用脚本，也能阅读正文、导航和打开 PDF。
图库禁用脚本时可通过 /playground/bandori/all/ 浏览并保存全部图片。
导航在 About、Notes、Blog 及 404.html 中分别存在；修改导航时同步修改这四个文件。
内容链接优先使用 /notes/ 等站内路径；不要添加外部字体、脚本或样式资源。
学术页页脚的 Off duty 链接通向 /playground/，四个学术页面的页脚保持一致。

本地预览
  在这个文件夹双击 preview.cmd，然后在浏览器打开：
    http://127.0.0.1:8080/
  修改文件后刷新网页。停止预览时在命令窗口按 Ctrl+C。

  在 Codex 终端中也可以运行：
    node tools/preview.mjs
  如果 8080 端口已占用，可以指定另一个端口：
    node tools/preview.mjs 8081

  预览脚本只使用 Node.js 自带模块，不需要 npm install。
  preview.cmd 会优先使用终端中的 Node，再尝试当前 Codex 自带的 Node。
  换电脑后若这两处都没有 Node，可安装官网版本：https://nodejs.org/
  Node 只用于可选的本地工具，线上网站不需要它。
  请通过本地服务器查看，不要直接双击 HTML，以免根路径链接无法正确打开。

发布前检查
  在 Codex 终端中运行：
    node tools/check.mjs
  此命令离线检查全部 HTML 的本地链接、页内锚点和外部运行资源。
  再在浏览器确认首页、笔记页、博客页、PDF 和手机窄屏显示。
  检查工具不检查 PDF 正文或外部网站的可用性。

课余小站与图库
  /playground/index.html 是课余小站入口；/playground/bandori/index.html 是可筛选图库。
  样式分别位于 playground/playground.css 与 playground/bandori/gallery.css。
  gallery.js 只使用浏览器原生 API，收藏留在 localStorage，不上传到服务器。
  图库按具体乐队、角色、整活/反应/台词/团子及动静态筛选，不再使用含义混杂的 OurNotes 分组。
  图片使用本站轻量 WebP 版本（含动画）。详情保留原帖、来源署名和原文件链接。
  data/catalog.json 提供检索数据；data/sources.json 是公开来源记录。
  原始下载素材不放入仓库，避免挤占 GitHub Pages 容量。不要将压缩包或临时文件提交进来。
  更新图片可使用 tools/build-meme-library.py（需要 Python 与 Pillow）：
    python tools/build-meme-library.py --catalog 原目录.json --asset-root 原图目录 --extra 新素材.json
  转换缓存写入 .local/（被 Git 忽略）；输出只包含网页资源与公开来源元数据。
  后续批次用 --previous-extra 传入早期补充清单，--extra 传入本轮清单，两项均可重复，
  --updated YYYY-MM-DD 设置本轮日期。图卡 ID 保持稳定，收藏和分享链接能继续使用。
  核过原图的角色、乐队、标题纠正记录在 tools/meme-corrections.json。characters 只列
  可辨认的入镜人物；speaker 单列来源站标注的说话角色。修正时也清理旧的误导性 tags。
  tools/meme-character-aliases.json 将常用译名和英文名关联到已确认的角色。
  更新后执行 node tools/finalize-playground.mjs 更新首页数字，并运行：
    node tools/check.mjs
    node tools/check-meme-library.mjs
    node tools/check-gallery-behavior.mjs
  另用浏览器检查桌面与手机布局、筛选、收藏、分享链接、动图预览与保存。

提交与上线
  gh-pages 是网站发布分支，origin 指向原来的 GitHub 仓库。
  日常维护时，常用流程是：
    git pull --ff-only
    （编辑并预览，然后运行 node tools/check.mjs）
    git diff
    git add （只填写本次需要发布的文件路径）
    git commit -m "Update personal website"
    git push origin gh-pages
  推送到 gh-pages 会更新线上个人主页，因此应在确认后执行。
